# PLAN 생성

TECHSPEC.md를 바탕으로 구현 계획서(PLAN.md)를 작성한다.

## 사전 조건

현재 디렉토리에 TECHSPEC.md가 존재해야 한다. 없으면 중단하고 `/techspec`을 먼저 실행하도록 안내한다.

## TECHSPEC 내용

!`cat TECHSPEC.md`

## 진행 방식

1. TECHSPEC의 §1 (구현), §3 (작업 목록), §7 (핵심 구현 로직)을 우선 참조한다.
2. `$ARGUMENTS`가 있으면 마일스톤 구성 힌트로 사용한다.
3. 마일스톤 목록 초안을 제시하고 사용자 확인을 받은 후 전체 PLAN.md를 생성한다.

## 마일스톤 설계 원칙

- 하나의 마일스톤 = 하나의 동작이 완성되는 단위 (단일 책임)
- TECHSPEC §2.2(2단계 항목)는 최초 PLAN에 포함하지 않는다 — MVP 구현 완료 후 필요 시 PLAN에 추가

**구현 순서**

1. 프로젝트 초기화
2. 스키마 & 모델
3. MVP 기능 — 각 기능 직후 P0 테스트 마일스톤을 붙인다
4. 첫 배포 — MVP 핵심 기능 완성 후 최대한 빨리
5. UI/스타일링 & QA
6. 최종 배포

**P0 테스트 배치 규칙**

- P0 = Priority 0. 실패하면 데이터가 오염되거나 비즈니스 규칙이 깨지는 테스트
- 해당 기능 마일스톤 바로 뒤에 위치시킨다 (마지막에 몰아넣지 않는다)

## 출력 구조

각 마일스톤은 다음 형식으로 작성한다:

```markdown
### Milestone N: [마일스톤명]

**목표:** [한 줄 설명]

> 📖 TECHSPEC 섹션 [X.X] 참조

**[테스트 유형] Tests**

- [ ] [테스트 케이스]

**완료 조건:** [검증 기준]

- Commits:
```

마지막에 P0 테스트 체크리스트를 테이블로 추가한다:

```markdown
## 🧪 P0 테스트 체크리스트

| 마일스톤 | 테스트 | 상태 |
| -------- | ------ | ---- |
| MN       | [설명] | [ ]  |
```

## 규칙

- 테스트 케이스를 구현 항목보다 먼저 나열한다 (TDD)
- 동시성/중복/마감 관련 테스트는 **(P0)** 으로 표시한다
- TECHSPEC에 정의된 에러 메시지는 테스트 케이스에 그대로 인용한다
- 구현 세부사항(코드 수준)은 TECHSPEC 참조로 대체하고 PLAN에 반복하지 않는다
- 완료 조건은 브라우저 또는 CLI에서 직접 확인 가능한 형태로 작성한다
